WHY TENSORRT RAFT WASN'T FASTER (LOCAL RTX 5070 HISTORY)
-----------------------------------------------------------
We built TensorRT RAFT engine and it WASN'T faster than PyTorch baseline.

Issues Discovered:
1. Stream Synchronization Overhead
   - TensorRT used default CUDA stream
   - Default stream blocks all other operations
   - Created dedicated stream (v3) but still no speedup

2. Memory Copy Overhead
   - PyTorch tensors → TensorRT device pointers
   - Conversion overhead negated TensorRT speedup
   - Even with direct pointer passing

3. Small Batch Sizes
   - RAFT processes 1-2 frames at a time
   - TensorRT benefits from batch sizes 32+
   - Our use case: batch=1-2, not enough parallelism

4. PyTorch Already Optimized
   - RAFT with FP16 autocast already fast (~4-5 it/s)
   - PyTorch 2.x JIT optimizations effective
   - Diminishing returns from TensorRT

Decision: Kept baseline PyTorch RAFT
Result: RAFT is NOT a bottleneck in the pipeline

Current Status (from TENSORRT_PROGRESS.txt):
  - RAFT engine: Built (7.4 MB, fastflownet)
  - Runtime: Wired into watermark.py with v3 I/O + CUDA stream
  - Mode: Can use TensorRT or PyTorch (fallback available)
  - Expected: 2-3x speedup on RTX 4090 vs GTX 1660 Ti benchmarks

CRITICAL FIXES REQUIRED (from TENSORRT_PROGRESS.txt lines 199-642):

FIX #1: PyTorch ONNX Argument Order (MOST CRITICAL!)
  Problem: deform_conv2d args passed in NON-STANDARD order during ONNX tracing

  Documented signature:
    deform_conv2d(input, offset, weight, bias, stride, padding, dilation, mask)

  ACTUAL PyTorch ONNX tracing order:
    args[0] = input (Concat node)
    args[1] = weight (prim::Param)  ← WEIGHT AT POSITION 1, NOT 2!
    args[2] = offset (Concat node)  ← OFFSET AT POSITION 2, NOT 1!
    args[3] = mask (Sigmoid node)
    args[4] = bias (prim::Param)

  Solution: export_rfcnet_onnx.py lines 64-68
    weight = args[1]  # NOT args[2]!
    offset = args[2]  # NOT args[1]!

  Impact: Wrong tensor order → plugin outputs wrong shapes → TensorRT build fails
  File: faster-propainter-main/tools/export_rfcnet_onnx.py

FIX #2: Remove cuDNN Tactic Source for Blackwell
  Problem: TensorRT 10.x doesn't support cuDNN tactics on Blackwell (RTX 5070/5090)
  Error: "TensorRT does not support cuDNN as a tactic source in Blackwell"

  Solution: BUILD_RFCNET_ENGINE_FP16.bat line 28
    --tacticSources=+CUBLAS  # REMOVED +CUDNN

  Note: RTX 4090 (Ada Lovelace) MAY support +CUDNN, but use +CUBLAS for consistency
  File: BUILD_RFCNET_ENGINE_FP16.bat

FIX #3: DCNv2 Plugin Compute Capability
  Problem: Plugin compiled for SM 80/86/89 only, crashes on Blackwell SM 90
  Error: "no kernel image is available for execution on the device"

  Solution: build_dcnv2_plugin.bat line 18
    CMAKE_CUDA_ARCHITECTURES="80;86;89;90"

  Note: RTX 4090 is SM 89, already covered by "89"
        RTX 5070 is SM 90, needs "90"
  File: build_dcnv2_plugin.bat

FIX #4: TensorRT Python CUDA Version Mismatch
  Problem: pip-installed tensorrt defaults to CUDA 13, system has CUDA 12.8
  Error: "Unable to load library: cublas64_13.dll"

  Solution:
    pip uninstall -y tensorrt tensorrt-cu13 tensorrt-cu13-bindings tensorrt-cu13-libs
    pip install tensorrt-cu12 tensorrt-cu12-bindings tensorrt-cu12-libs

  Verification:
    pip show tensorrt | grep Requires
    # Should show: tensorrt_cu12 (not cu13)

PART 7: TROUBLESHOOTING GUIDE
================================================================================

ISSUE: TensorRT Engine Fails to Load on RTX 4090
--------------------------------------------------
Symptom: "Error Code 6: API Usage Error"
Possible Causes:
  1. Wrong CUDA version (cu13 vs cu12)
     Solution: pip install tensorrt-cu12 tensorrt-cu12-bindings tensorrt-cu12-libs

  2. TensorRT DLLs not in PATH
     Solution: Run SETUP_TRT_ENV.bat before starting Celery

  3. Engine built for wrong arch (should work - both SM 89)
     Solution: Rebuild engine on RTX 4090 if needed

ISSUE: "no kernel image available" Error
------------------------------------------
Symptom: Engine loads but fails at runtime with CUDA error
Cause: Plugin compiled without SM 89 support
Solution: Rebuild DCNv2 plugin with CMAKE_CUDA_ARCHITECTURES="80;86;89;90"
File: build_dcnv2_plugin.bat

ISSUE: Out of Memory (OOM) Errors
-----------------------------------
Symptom: CUDA OOM during inference
Cause: Concurrency too high for available VRAM
Solution:
  1. Check VRAM usage: nvidia-smi
  2. Reduce concurrency: concurrency=4 → concurrency=3
  3. Monitor per-frame VRAM spikes (complex scenes use more memory)

ISSUE: Slower Than Expected Performance
-----------------------------------------
Possible Causes:
  1. Not using TensorRT engines
     Check: Look for "[OK] TensorRT engine loaded" in logs
     Solution: Verify YOLO_REQUIRE_TENSORRT=1, check engine paths

  2. Using wrong GPU
     Check: nvidia-smi (which GPU is being used)
     Solution: Set CUDA_VISIBLE_DEVICES=0 (4090)

  3. Triton/Flash Attention not installed
     Check: pip list | grep triton, pip list | grep flash-attn
     Solution: Install optimization packages (Phase 3)

  4. RFCNet TensorRT not wired
     Check: Look for RFCNet TensorRT logs
     Solution: Set RFCNET_TORCHTRT=1, verify engine exists

ISSUE: Triton Compilation Errors
----------------------------------
Symptom: Triton fails to import or compile kernels
Cause: Missing Visual Studio C++ compiler
Solution:
  1. Install Visual Studio 2022 Build Tools
  2. Ensure vcvars64.bat called before running Python
  3. START_CELERY.bat already does this (line 8-11)

ISSUE: Driver/CUDA Version Mismatch
-------------------------------------
Symptom: "CUDA driver version is insufficient"
Cause: Driver too old for CUDA 12.8
Solution: Install NVIDIA driver 545+ (latest recommended)

ISSUE: Multi-GPU Workers Not Load Balancing
---------------------------------------------
Symptom: One GPU idle while other is working
Cause: Celery routing issue or wrong CUDA_VISIBLE_DEVICES
Solution:
  1. Verify both workers connected to same Redis
  2. Check worker hostnames are unique (worker_4090@%h vs worker_5070@%h)
  3. Verify CUDA_VISIBLE_DEVICES set correctly per worker

PART 10: POWER CONNECTOR SPECIFIC DETAILS
================================================================================

12VHPWR CONNECTOR ANATOMY:
---------------------------
Physical Connector:
  - 16 pins total
  - 12 power pins (6 pairs)
  - 4 sense pins (signal)

Power Delivery:
  - 12 pins: 12.5A each = 150W per pair
  - Total: 600W maximum (6 pairs × 100W)
  - RTX 4090: Uses up to 450W (3.75 pairs)
  - RTX 5070: Uses up to 220W (1.83 pairs)

SAFE CONNECTION METHODS:
--------------------------
Method 1: Native 12VHPWR Cable (BEST)
  - Single cable from PSU to GPU
  - Supports full 600W
  - No adapters needed
  - Cleanest installation

Method 2: 4x PCIe 8-pin to 12VHPWR Adapter (GOOD)
  - Uses 4 separate PCIe cables from PSU
  - Each cable on separate 12V rail
  - Supports 600W (150W per cable × 4)
  - Ensure cables NOT daisy-chained!

Method 3: 3x PCIe 8-pin to 12VHPWR Adapter (ACCEPTABLE)
  - Uses 3 separate PCIe cables
  - Supports 450W (150W per cable × 3)
  - Sufficient for RTX 4090 (450W TDP)
  - Ensure cables NOT daisy-chained!

DANGEROUS CONNECTION (AVOID):
-------------------------------
❌ Daisy-Chained 8-pin Cables
  - Single cable splits into 2x 8-pin connectors
  - Overloads single 12V rail
  - Can cause cable melting/fire
  - Common with older PSUs

Identification:
  - Look at cable: Does it split into 2 connectors?
  - Trace back to PSU: How many cables leave PSU?
  - Safe: Each 8-pin connector has dedicated cable to PSU
  - Unsafe: Multiple 8-pin connectors from single cable

CHECKING YOUR PSU:
-------------------
1. Find PSU model number (label on PSU)
2. Google: "[PSU model] specifications"
3. Check:
   - Total wattage (need 850W minimum)
   - 12V rail amperage (need 60A+ total)
   - PCIe connectors (need 2x 12VHPWR OR 6x 8-pin)

Example Good PSUs:
  - Corsair RM1000x (1000W, 4x 12VHPWR native)
  - EVGA SuperNOVA 1000 G6 (1000W, 2x 12VHPWR native)
  - Seasonic PRIME TX-1000 (1000W, multiple PCIe 8-pin)

POWER CONSUMPTION MONITORING:
-------------------------------
While Running Celery:
  nvidia-smi dmon -s p -c 60
  # Shows power draw in watts every second
  # Watch for spikes (can exceed TDP briefly)

Expected Power Draw:
  - RTX 4090: 350-450W under load (spikes to 500W)
  - RTX 5070: 180-220W under load (spikes to 250W)
  - Total GPU: 530-670W sustained, 750W spikes
