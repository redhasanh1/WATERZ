## WHY TENSORRT YOLO ENGINE FAILED
--------------------------------------------------------------------------------
PROBLEM: RTX 5070 TensorRT engine segfaults on RTX 5090
CAUSE:   GPU architecture mismatch
  - RTX 5070 = Ada Lovelace (SM 8.9)
  - RTX 5090 = Blackwell (SM 12.0)
  - TensorRT engines are GPU-architecture-specific

ATTEMPTED FIX: Build RTX 5090 engine on vast.ai
BLOCKER: Driver/TensorRT version catch-22
  - vast.ai driver: 570.181
  - Driver 570.181 supports: TensorRT ≤10.6
  - TensorRT ≤10.6 supports: Up to SM 8.9 (NO Blackwell SM 12.0)
  - TensorRT 10.13+ supports: SM 12.0 (Blackwell)
  - TensorRT 10.13+ requires: Driver 570.195+

SOLUTION: Switch to PyTorch YOLO (best.pt)
  - Frame-by-frame detection (no batching)
  - Works on any GPU architecture
  - 6MB vs 11MB (smaller!)

## VAST.AI MANUAL FIXES (Until Docker rebuild)
--------------------------------------------------------------------------------
After every reboot, run these commands:

1. Install build tools:
   apt-get update && apt-get install -y build-essential python3.11-dev

2. Create CUDA symlink:
   ln -s /usr/lib/x86_64-linux-gnu/libcuda.so.1 \
         /usr/lib/x86_64-linux-gnu/libcuda.so

3. Downgrade imageio:
   python3.11 -m pip install --force-reinstall --no-cache-dir imageio==2.34.2

4. Download missing files:
   cd /app
   curl -L https://raw.githubusercontent.com/redhasanh1/WATERZ/hasan/crop_utils.py -o crop_utils.py
   curl -L https://raw.githubusercontent.com/redhasanh1/WATERZ/hasan/segment_detector.py -o segment_detector.py
   curl -L https://raw.githubusercontent.com/redhasanh1/WATERZ/hasan/yolo_detector.py -o yolo_detector.py
   curl -L https://raw.githubusercontent.com/redhasanh1/WATERZ/hasan/server_production.py -o server_production.py
   mkdir -p runs/detect/new_sora_watermark/weights
   curl -L https://github.com/redhasanh1/WATERZ/raw/hasan/runs/detect/new_sora_watermark/weights/best.pt \
        -o runs/detect/new_sora_watermark/weights/best.pt

5. Start Celery:
   cd /app
   export REDIS_URL="redis://:watermarkz_secure_2024@0.tcp.ngrok.io:11917/0"
   python3.11 -m celery -A server_production.celery worker --loglevel=info --pool=threads --concurrency=2
