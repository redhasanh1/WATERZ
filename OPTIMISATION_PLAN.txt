Phase 1 — YOLOv8 To TensorRT (FP16/INT8)
Files and locations:
- Model (.pt): web/yolo_weights/sora_best.pt (or runs/detect/new_sora_watermark/weights/best.pt)
- Detector code: yolo_detector.py:12 (auto-picks TRT if engine exists; respects env)
- Engine destination directory: runs/detect/new_sora_watermark/weights/

Export and build:
1) Export YOLO to ONNX (Ultralytics):
   - Command example (PowerShell):
     yolo export model="runs/detect/new_sora_watermark/weights/best.pt" format=onnx dynamic=True opset=12 imgsz=640 simplify=True
   - Output: runs/detect/new_sora_watermark/weights/best.onnx

2) Build TensorRT engine(s) with trtexec:
   - FP16 engine:
     trtexec --onnx=runs/detect/new_sora_watermark/weights/best.onnx ^
             --saveEngine=runs/detect/new_sora_watermark/weights/best_fp16.engine ^
             --fp16 --workspace=4096 --useSpinWait ^
             --tacticSources=+CUBLAS,+CUDNN --timingCacheFile=runs/detect/new_sora_watermark/weights/trt_timing_cache

   - INT8 engine (requires calibration cache):
     trtexec --onnx=runs/detect/new_sora_watermark/weights/best.onnx ^
             --saveEngine=runs/detect/new_sora_watermark/weights/best_int8.engine ^
             --int8 --calib=web/cache/calib/yolo.calib ^
             --fp16 --workspace=8192 --useSpinWait ^
             --tacticSources=+CUBLAS,+CUDNN --timingCacheFile=runs/detect/new_sora_watermark/weights/trt_timing_cache

3) Force engine use in production:
   - Environment variables:
     - YOLO_REQUIRE_TENSORRT=1
     - Optional explicit engine path: YOLO_TENSORRT_ENGINE=runs/detect/new_sora_watermark/weights/best_int8.engine

Notes:
- Prefer exporter variants that fuse NMS as a TensorRT plugin (Ultralytics supports TRT-friendly export). If not embedded, use TRT-YOLO NMS plugin.
- Expected latency on RTX 4090 (batch=1): INT8 ≈ 1–2 ms @ 640, FP16 ≈ 2–3.5 ms.

Track A (fast iteration): Torch-TensorRT compile
1) Install torch_tensorrt matching your PyTorch/CUDA.
2) In faster-propainter-main/watermark.py, after model load and .eval().cuda(), compile modules:
   - Example (concept):
     import torch_tensorrt as trt
     raft_trt = trt.compile(raft_module, inputs=[trt.Input([1,3,H,W]), trt.Input([1,3,H,W])], enabled_precisions={torch.float16}, workspace_size=2<<30)
     gen_trt  = trt.compile(inpaint_gen, inputs=[trt.Input([1,3,H,W]), trt.Input([1,1,H,W])], enabled_precisions={torch.float16})
     rfc_trt  = trt.compile(rfc_module,   inputs=[...], enabled_precisions={torch.float16})
   - Persist compiled engines (if supported): save to faster-propainter-main/engines/... for reuse.
3) Keep input shapes divisible by 8/16 and limit dynamic profiles to a small set: {128,160,192,256,320,384} for ROI crops.

Track B (max performance): ONNX + TensorRT per sub-net
1) Write exporters (new scripts under faster-propainter-main/tools/) to load weights and export ONNX for each module with dynamic H/W (bounded profiles).
   - Example outputs:
     - faster-propainter-main/engines/raft/raft.onnx
     - faster-propainter-main/engines/rfcnet/rfcnet.onnx
     - faster-propainter-main/engines/propainter/propainter.onnx
2) Build with trtexec (FP16 first, consider INT8 for inpaint convs):
   - RAFT FP16:
     trtexec --onnx=faster-propainter-main/engines/raft/raft.onnx ^
             --saveEngine=faster-propainter-main/engines/raft/raft_fp16.engine ^
             --fp16 --workspace=4096 --useSpinWait --tacticSources=+CUBLAS,+CUDNN
   - RFCNet FP16:
     trtexec --onnx=faster-propainter-main/engines/rfcnet/rfcnet.onnx ^
             --saveEngine=faster-propainter-main/engines/rfcnet/rfcnet_fp16.engine ^
             --fp16 --workspace=4096
   - Inpaint Generator FP16:
     trtexec --onnx=faster-propainter-main/engines/propainter/propainter.onnx ^
             --saveEngine=faster-propainter-main/engines/propainter/propainter_fp16.engine ^
             --fp16 --workspace=4096
3) Integration hook: in faster-propainter-main/watermark.py, wrap calls to prefer TRT runners when engine files exist; fallback to PyTorch module if not.
4) Plugins: if deformable conv or exotic ops block export, either:
   - Replace with plugin kernels, or
   - Keep those layers in Torch-TRT fallback, or
   - Use simplified approximations for speed-critical use cases.
