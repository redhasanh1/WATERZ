FIX #1: PyTorch ONNX Argument Order (MOST CRITICAL)
-----------------------------------------------------
Problem: torchvision::deform_conv2d has no ONNX symbolic function

Discovery: PyTorch passes deform_conv2d arguments in NON-STANDARD order during
           ONNX tracing, different from torchvision.ops.deform_conv2d signature

Documented Signature:
  deform_conv2d(input, offset, weight, bias, stride, padding, dilation, mask)

ACTUAL PyTorch ONNX Tracing Order:
  args[0] = input (Concat node)
  args[1] = weight (prim::Param - convolution weight tensor!)
  args[2] = offset (Concat node)
  args[3] = mask (Sigmoid node)
  args[4] = bias (prim::Param)
  args[5-13] = stride/padding/dilation constants

Solution in export_rfcnet_onnx.py (lines 64-68):
  input_arg = args[0]
  weight = args[1]     # CRITICAL: weight at position 1, not 2!
  offset = args[2]     # offset at position 2, not 1!

--------------------------------------------------------------------------------
 LESSONS LEARNED
--------------------------------------------------------------------------------

1. PyTorch ONNX Tracing Argument Order is Non-Deterministic
   - NEVER assume PyTorch passes args in documented signature order
   - ALWAYS use debug logging to inspect actual arg order during tracing
   - Use symbolic_helper functions to inspect tensor types/shapes
   - Cross-reference with model architecture to validate extracted tensors

2. Blackwell Architecture Has Specific Restrictions
   - TensorRT 10.x does not support cuDNN tactic source on Blackwell
   - Always use --tacticSources=+CUBLAS only for RTX 50-series
   - Future TensorRT versions may lift this restriction
   - DCNv2 plugin can still use cuDNN internally (separate concern)

3. Custom TensorRT Plugins Require Explicit Compute Capability
   - Plugin must be compiled for target GPU's SM version
   - CMAKE_CUDA_ARCHITECTURES must include CC 90 for Blackwell
   - "no kernel image available" = missing SM version in plugin build
   - Verify --generate-code output during plugin compilation

4. UTF-8 Encoding Issues on Windows CMD
   - Avoid UTF-8 symbols in Python scripts run from batch files
   - Use ASCII alternatives: [OK], [SUCCESS], [WARNING]
   - Affects print statements, not file I/O or ONNX export

5. ONNX Shape Inference Metadata is Ignored by Custom Plugins
   - Attempted fixes using onnx.shape_inference or setType() don't help
   - Custom plugins implement their own getOutputDimensions()
   - Shape issues must be fixed in plugin source or ONNX symbolic function
   - TensorRT doesn't validate ONNX shape metadata for custom ops

6. mmdeploy DCNv2 Plugin Reads Weight Shape Directly
   - Plugin uses inputs[3] (weight tensor) to determine output channels
   - weight.shape[0] = output channels for deformable conv
   - Wrong tensor at inputs[3] -> wrong output shape
   - No error/warning from plugin, just incorrect dimensions
